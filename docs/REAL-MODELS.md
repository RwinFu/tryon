# مدل‌های واقعی و مرز دقت پیش‌نمایش

## کاتالوگ

`src/frame/catalog.js` مرجع اصلی داده‌هاست؛ `products.json` از آن با `node tools/case-catalog.mjs` ساخته می‌شود. هر رکورد کد مدل/رنگ، سایز چاپی، نوع منبع و پیوند همان صفحه را نگه می‌دارد. تاریخ بازبینی پیوند در `sourceChecked` ثبت می‌شود.

- **Ray-Ban (AR-101 تا AR-112):** کد رنگ/مدل، جنس، رنگ عدسی، اندازه‌های چاپی و ارتفاع عدسی از صفحهٔ رسمی مدل خوانده شده‌اند.
- **Police (AR-113 تا AR-119):** صفحه‌های رسمی مدل، کد رنگ، جنس و اندازهٔ لنز/پل/دسته را تأیید می‌کنند. Police در این صفحات ارتفاع عدسی را درج نمی‌کند؛ ارتفاع‌های `lensH` با `lensHSource: "estimated"` علامت خورده‌اند.
- **Cartier (AR-120 تا AR-125):** شناسهٔ مرجع و سه اندازه از صفحهٔ رسمی محصول هستند. صفحه‌های بررسی‌شده ارتفاع عدسی را منتشر نکرده‌اند، بنابراین آن مقدار تخمینی است.
- **Chrome Hearts (AR-126 تا AR-128):** کد/رنگ/سایز از صفحات فروشندگان یا فهرست‌های بازار ثانویه آمده است، نه صفحهٔ رسمی سازنده. این پروژه اصالت، موجودی یا ارتباط فروشنده با برند را تأیید نمی‌کند؛ ارتفاع عدسی نیز تخمینی است.

صفحه‌ها و حدود مستندات در پیوندهای `sourceUrl` هر محصول مشخص‌اند. برای بازبینی دستی از همان پیوند استفاده کنید؛ قیمت، موجودی و رنگ‌بندی ممکن است با منطقه و زمان تغییر کنند.

## سه‌بعدی: کاتالوگ واقعی، ولی هنوز فایل رسمیِ محصول نیست

هیچ مدل سه‌بعدی رسمی یا اسکنِ مجاز و تأییدشده برای همین SKUها در مخزن نیست. جست‌وجوی فایل‌های عمومی، مدل‌های کلیِ «Ray-Ban/eyewear» را نشان داد، نه فایلِ قابل‌تطبیق با کد/سایز/رنگ هر SKU؛ بنابراین از آن‌ها استفاده نشد. برای هر محصول وضعیت `modelAssetStatus: "procedural-preview"` نمایش داده می‌شود. موتور یک فرم رویه‌ایِ میلی‌متری را از اندازه و خانوادهٔ سیلوئت می‌سازد؛ حلقه، پل، دسته، محل فلز/استات و رنگ عدسی به مدل نزدیک شده‌اند، اما جزئیات تزئینی و انحنای دقیق با SKU یکی نیستند. بنابراین کارت عمداً «پیش‌نمایش هندسی» می‌گوید، نه تصویر دقیقِ کالای فروش.

برای نمایش **همان نمونهٔ فیزیکی** باید GLB تهیه‌شده با مجوز مناسب و متعلق به همان SKU اضافه شود. موتورِ بارگذاری موجود در `src/frame/loaders.js` و `src/engine/stage.js` این کلیدها را می‌خواند:

```json
{
  "glb": "assets/frames/RB2140-901-58.glb",
  "widthMM": 138,
  "glbRotation": [0, 0, 0],
  "glbOffset": [0, 0, 0],
  "glbScale": 1
}
```

`widthMM` پهنای واقعی کل فریم است (نه `2 × lensW + dbn`، که فقط عرض فرانت از روی اندازهٔ چاپی را تخمین می‌زند). پیش از تغییر وضعیت مدل، تطبیق رنگ/سایز/SKU را بازبینی و منشأ، مجوز و نام سازندهٔ فایل را در `modelAssetSource`، `modelAssetLicense` و `modelAssetAttribution` ثبت کنید؛ فایل مدل را بدون مجوز در مخزن یا وب‌سایت قرار ندهید. سپس `products.json` را دوباره تولید کنید و GLB را در تست `test/glb.test.mjs` و روی چند زاویه بازبینی کنید.

## ساخت دوباره و کنترل صحت

```bash
node tools/case-catalog.mjs
npm test
npm run build
```

تست هندسه کنترل می‌کند شکل‌ها ابعاد چاپی لنز را تغییر ندهند، contour داخلی/بیرونی در جهت درست offset شود، و همهٔ ۲۸ رکورد بدون مختصات/اندیس نامعتبر مش بسازند. این تست‌ها شکل و سایز را اعتبارسنجی می‌کنند؛ جای تطبیق تصویری با فریم فیزیکی یا تأیید optician را نمی‌گیرند.
