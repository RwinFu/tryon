# مشخصهٔ رفتاریِ شِلِ «پرو با دوربین»

سندِ رفتارمحور (بدون نامِ متغیر یا کد). جایگزینِ چیدمانِ قبلیِ ۱۳ عنصری می‌شود.
مرجعِ خروجی: `docs/UI-XRAY.md`.

## ۱. اصل

یک قابِ دوربین که عینک روی صورت است، و یک «قفسهٔ» کوچک پایینِ صفحه برای انتخاب و خرید.
هر چیزی که یکی از این چهار کار را نکرد، از دیدِ مشتری حذف می‌شود:
**دیدن · عوض کردن · اندازه‌دانستن · خریدن**.

## ۲. صفحه‌ها

### ۲.۱ خوش‌آمد
- نمایشِ برند، یک جملهٔ کوتاه دربارهٔ کاری که می‌شود کرد، و خطِ حریمِ خصوصی.
- دو اقدام: «روشن کردن دوربین» (اصلی) و «از عکس» (ثانویه، اگر دارد).
- اگر فریمی از قبل انتخاب شده، نام و سایزِ آن در یک سطرِ کوچک دیده می‌شود.
- حالت‌ها: آماده‌سازی (چرخنده + متن)، خطا (پیامِ فارسیِ روشن + دکمهٔ تلاشِ دوباره).

### ۲.۲ پروی زنده
- قابِ دوربین تمام‌صفحه (در نمایشگرِ بزرگ، کارتِ عمودیِ وسط‌چین روی زمینهٔ تیره).
- نوارِ بالا: «بستن» در سمتِ شروع، نامِ برند در سمتِ پایان. هیچ دکمهٔ دیگری.
- پیامِ وضعیت تنها وقتی حرفی هست («دنبال صورت می‌گردم…»)، یک خطِ کوتاه، بالای صحنه؛
  پس از قفل‌شدن روی صورت ناپدید می‌شود.
- راهنمای کادرِ صورت فقط تا قبلِ قفل‌شدن؛ بعد محو می‌شود.

### ۲.۳ قفسه (پایین)
چهار ردیف، همگی همیشه دیده می‌شوند:
1. نامِ فریم (برند · نام · رنگ) و قیمت (یا سایز اگر قیمتی نیست).
2. حکمِ فیت: یک خط با نقطهٔ رنگی — «اندازهٔ صورتت است» / «کمی تنگ یا گشاد» / «اندازه معلوم نیست».
3. کارت‌های فریم: فقط تصویرِ رندرشدهٔ فریم، انتخاب‌شده با حاشیهٔ روشن و کمی بالا؛
   کارتِ انتخاب‌شده هنگام جابه‌جایی به وسط می‌آید.
4. یک دکمهٔ اصلی: «افزودن به سبد».
- نقطه‌های رنگ فقط اگر فریم بیش از یک رنگ دارد.
- برچسبِ متنی روی کارت‌ها نیست (نام در ردیف ۱ است).

### ۲.۴ پرو روی عکس
همان قفسه، با یک دکمهٔ کوچکِ «دوربین» در نوارِ بالا برای برگشتن. تصویرِ آپلود با `contain`
نمایش داده می‌شود تا چیزی بریده نشود.

### ۲.۵ پنل‌های اختیاری (خاموش به‌صورت پیش‌فرض)
- «برگهٔ فیت» (چهار عددِ میلی‌متری + ردیف‌های فیت + ورودی PD): فقط اگر فروشگاه روشن کند.
- «اسکنِ صورت» (سه مرحله، جدول، مشِ سه‌بعدی، دانلود): فقط اگر فروشگاه روشن کند.
- «عکس‌گرفتن»: فقط اگر فروشگاه روشن کند؛ خروجی همیشه از رویداد `tryon:snapshot` در دسترس است.

## ۳. حالت‌ها و خطاها

| حالت | آنچه مشتری می‌بیند |
|---|---|
| اجازه رد شد | پیامِ «اجازهٔ دوربین داده نشد» + راهِ «از عکس» |
| دوربین نیست | پیامِ «دوربینی پیدا نشد» + راهِ «از عکس» |
| HTTPS لازم | پیامِ روشن + راهِ «از عکس» |
| صورت در کادر نیست | خطِ «دنبال صورت می‌گردم…» بدون دکمه |
| عکس بدون صورت | پیامِ «در این عکس صورتی پیدا نشد» و ماندن در همان صفحه |
| سبد | تُستِ «به سبد اضافه شد» بالای قفسه، بدون پوشاندنِ آن |

## ۴. دسترس‌پذیری

- هر دکمه‌ای که فقط آیکن دارد، `aria-label` دارد.
- دکمهٔ اصلی ≥ ۴۸px ارتفاع؛ کارتِ فریم ≥ ۴۴px.
- حرکتِ `prefers-reduced-motion` خاموش می‌شود.
- فوکوسِ صفحه‌کلید در ریلِ فریم‌ها با جهت‌های راست/چپ (RTL-aware) حرکت می‌کند.

## ۵. رویدادها (بدون تغییر)

`tryon:ready · product · variant · snapshot · cart · fit · faceshape · error`
— حذفِ عنصرِ رابط، رویداد را حذف نمی‌کند؛ فروشگاه همان داده را می‌گیرد.

## ۶. تستِ پذیرش

1. ۳۶۰×۶۴۰: هیچ عنصری روی چشم/فریم نیفتد؛ همهٔ ردیف‌های قفسه دیده شوند.
2. ۳۹۰×۵۶۰ (افقی/کوتاه): ریلِ فریم‌ها حذف نشود.
3. لمسِ کارت → فریم عوض شود، کارت به وسط بیاید، نام و قیمت به‌روز شود.
4. «از عکس» → فایل → پرو روی عکس؛ دکمهٔ «دوربین» برگرداند.
5. اجازهٔ ردشده → پیام + راهِ عکس.
6. `fitSheet` روشن → برگه باز شود؛ خاموش → هیچ عنصری در DOM نباشد.
